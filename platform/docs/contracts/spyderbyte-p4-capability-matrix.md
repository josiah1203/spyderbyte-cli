# Spyderbyte P4 capability matrix

This matrix records the implementation evidence for harness creation, invocation enforcement,
context trust boundaries, model/tool interception, Cline compatibility, and report acceptance.

| P4 workstream                         | Contract and implementation evidence                                                                                                                                                                                                                                    | Focused evidence                                                                                      |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Harness definition and factory        | `packages/harness-core/src/definition.ts` validates tier capability, policy consistency, hooks, tools, authority, budget, retries, plugins, and acceptance requirements.                                                                                                | `packages/harness-core/tests/harness.test.ts`; `packages/harness-core/tests/p4-completion.test.ts`    |
| Invocation and delegation enforcement | `packages/harness-core/src/invocation.ts` applies the tier matrix, registration/compatibility, input schema, authority, budget, depth, child-count, stale-parent lifecycle, and transaction checks; `packages/state` supplies authoritative child counts and row locks. | `packages/harness-core/tests/harness.test.ts`; state package tests                                    |
| Trust-separated context               | `packages/harness-core/src/context.ts` emits a source/version/size/reason manifest, tier-specific visibility, bounded prompts, and untrusted external content.                                                                                                          | `packages/harness-core/tests/p4-completion.test.ts`                                                   |
| Model routing and metering            | `packages/harness-core/src/model.ts` reserves/reconciles budgets, enforces tokens, records provider/model/policy/usage with correlation IDs, emits telemetry/audit, supports cancellation/deadlines, and bounds fallback without raw context.                           | `packages/harness-core/tests/model.test.ts`                                                           |
| Cline adapter boundary                | `packages/cline-adapter` owns the SDK-shaped surface and maps streamed events, usage, cancellation, disposal, and normalized failures to the internal adapter contract.                                                                                                 | `packages/cline-adapter/tests/compatibility.test.ts`                                                  |
| Hooks and tool interception           | `packages/harness-core/src/pipeline.ts` enforces ordered hooks and fail-closed critical behavior; `packages/tool-broker/src/broker.ts` carries invocation correlation through policy, budget, execution, and audit.                                                     | `packages/harness-core/tests/p4-completion.test.ts`; tool-broker tests                                |
| Report validation and commit boundary | `packages/harness-core/src/reports.ts` requires authoritative artifact, lineage/hash, cost, metric, child, state, identity, status, and acceptance verification before `reportCommitter` runs.                                                                          | `packages/harness-core/tests/p4-completion.test.ts`                                                   |
| Registry and Tier 2 shells            | `packages/harness-core/src/registry.ts` and `base-harnesses.ts` provide status/disable, exact compatibility, permitted-child, deterministic, plugin, and coding shell contracts; `packages/agent-registry` mirrors registry rules.                                      | `packages/harness-core/tests/p4-completion.test.ts`; `packages/agent-registry/tests/registry.test.ts` |

The focused P4 suites are supplemented by package typechecks/builds and the repository verification
gates. Invalid reports are rejected before the optional durable report committer is invoked.
